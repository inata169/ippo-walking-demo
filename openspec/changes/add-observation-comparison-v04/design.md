# Design: Ver.0.4「感覚と動きを比べる」

## Context

Ver.0.3は、設定値と歩行周期から説明用の3D姿勢を決定論的に生成する。実測歩行を再生するモデルではなく、足底圧や関節負荷も計算しない。この性質を保ったまま、端末内動画、本人の身体感覚、過去の設定を観察材料として加える。

## Goals

- 動画を見ながら3Dモデルを手動で近づけられる。
- 連続再生だけでなく、重要な場面で止めて観察できる。
- 片麻痺歩行で重要な左右差を表現できる。
- 見える動きと本人の感覚を混同せず、1件の観察記録として扱える。
- 異なる時期・条件の2記録を同じ条件で比較できる。
- 現行の匿名性、端末内処理、医学的限界の説明を維持する。

## Non-goals

- 動画解析、モーションキャプチャー、数値計測の代替
- 原因推定、将来予測、治療効果判定
- 痛みや疲労の医学的評価
- クラウド保存、アカウント、共有データベース

## Decisions

### 1. 動画は参照資料としてのみ扱う

`<input type="file" accept="video/*">` で選択し、`URL.createObjectURL()`を使ってブラウザー内に表示する。動画ファイルやファイル名はアプリの保存データへ含めない。動画を交換した時と画面終了時にObject URLを解放する。

動画と3Dの自動同期は行わない。利用者は双方を一時停止し、同じように見える場面を手動で合わせる。これは「簡易的な観察支援」という範囲を明確に保つためである。

### 2. 観察場面はモデル周期の固定位置とする

`phases.js` に動かしにくい側を基準とした6個の観察位置を定義する。

| ID | 画面表示 | 意図 |
|---|---|---|
| `footContact` | 足を着く | 動かしにくい側の足を着く直前後を見る |
| `acceptWeight` | 身体を支え始める | 体幹、膝、足首の位置を見る |
| `midSupport` | 足で支える | 支持中の姿勢を見る |
| `footOff` | 足が床から離れる | 振り出しへの移行を見る |
| `midSwing` | 足を前へ出す | 足の高さ、外回し、骨盤を見る |
| `nextContact` | 次の一歩を着く | 一歩の終わりを見る |

各位置の周期値は説明用モデルの内部定数であり、臨床的な歩行イベント測定値として表示しない。値はリハビリ専門職の確認後に確定する。

場面を選ぶと3D再生を停止し、該当周期へ移動する。A/B切替時は周期を変えない。

### 3. 左右差は既存設定への追加値として表す

設定UIには「動かしにくい側」と「反対側」の2群を設け、選択中の左右も併記する。追加候補は次の4項目とする。

| 項目 | 表示単位 | 意味 |
|---|---|---|
| 一歩の長さ | モデルcm | 左右それぞれの前後移動量 |
| 足の上がり方 | 0〜100 | 説明用の相対調整値 |
| 膝の曲がり | 0〜100 | 説明用の相対調整値 |
| 支える時間 | 周期% | 左右それぞれの接地継続時間 |

初期値ではVer.0.3と同じ見た目になるようにする。値は臨床尺度や実測値ではなく、既存のモデル設定と同様に正規化・範囲制限する。

左右で異なる一歩の長さを導入すると、現在の単一`strideFor()`だけでは足の接地位置を決められない。各脚の接地位置を累積しても、接地中の足が世界座標で滑らないことを優先する。骨盤の進行量は左右一歩の合計を1周期の進行量として計算する。

### 4. 身体感覚は構造化データとして分離する

見える動きの`config`と、本人の感覚を表す`observation`を別オブジェクトにする。自由記述は設けない。

```json
{
  "recordedMonth": "2026-09",
  "conditions": ["usual", "withCane", "withOrthosis", "beforeFatigue"],
  "ease": "comfortable",
  "endurance": "short",
  "sensations": ["heavyLeg", "toeCatchConcern"],
  "feltRegions": ["lowerBack", "knee"]
}
```

- `recordedMonth`: 任意の年月。日付や時刻は保存しない。
- `conditions`: 普段、疲労前、疲労後、杖あり・なし、装具あり・なし。
- `ease`: 楽、どちらでもない、つらい、分からない。
- `endurance`: 短時間向き、長時間でも同様、分からない。
- `sensations`: 重い、引っかかりそう、不安定、痛み、しびれ、力が必要、特になし。
- `feltRegions`: 腰、股関節、大腿、膝、下腿、足首、足部、その他、特になし。

画面では「実際の負荷」ではなく「本人が負担・違和感を感じる部位」と説明する。

### 5. 既存設定と経時記録の形式を分ける

Ver.0.3の`ippo-walking-settings` version 1は変更せず、読み書きを維持する。新しい記録は次の別形式とする。

```json
{
  "format": "ippo-walking-record",
  "version": 1,
  "config": {},
  "phase": 0.0,
  "observation": {}
}
```

`records.js` は許可フィールド、列挙値、数値範囲、最大ファイルサイズを検証する。未知フィールドは保持しない。読み込み失敗時は現在の画面状態を変更しない。動画、動画名、氏名、患者ID、自由記述は含めない。

### 6. 比較は同じ3D画面と周期を共有する

比較対象A/Bは、既存のA/B切替と同じ3D画面、カメラ方向、ズーム、周期を共有する。これにより表示条件の違いを減らす。同時に次の差分表を表示する。

- 左右別の4調整項目
- 既存の詳細調整項目
- 記録年月と条件タグ
- 楽さ、持続しやすさ、感覚、本人が感じる部位

値の大小を良い・悪い、改善・悪化として色分けしない。「以前」「現在」も固定せず、A/Bと表示する。

## Module responsibilities

| モジュール | 責務 |
|---|---|
| `patterns.js` | 左右別項目の定義、範囲、既定値、正規化 |
| `gait.js` | 左右別設定から説明用姿勢を生成 |
| `phases.js` | 6観察場面と周期位置の定義 |
| `video.js` | ローカル動画の選択、表示、解放、エラー表示 |
| `records.js` | 経時記録JSONの作成、検証、読込 |
| `comparison.js` | A/B差分データの作成 |
| `state.js` | 動画以外の画面状態、A/B、選択中の観察場面 |
| `app.js` | UIイベント、再生制御、ファイル操作 |
| `settings.js` | Ver.0.3設定JSONとの互換性維持 |

## Error handling

- 動画がブラウザーで再生できない場合は、3D設定を変えずに形式非対応を表示する。
- 動画を閉じても3D設定と観察記録は保持する。
- 記録JSONが不正な場合は、A/Bおよび現在設定を変更しない。
- 左右設定の組み合わせで脚長制約を満たせない場合は、現行の骨盤高制約を適用し、開発用状態として検出可能にする。

## Testing strategy

テストは主要動作と安全上重要な条件に絞る。

- 観察場面選択で停止し、有限な姿勢が得られる。
- 左右の片方だけを変更した時、反対側の設定値が変わらない。
- 接地中の足が世界座標上で滑らない。
- 既存設定JSON version 1を読み込める。
- 記録JSONの往復、範囲外値、未知形式、過大ファイルを検証できる。
- 記録JSONに動画情報、氏名、自由記述が含まれない。
- A/B切替で周期とカメラ条件が変わらない。

動画再生自体はブラウザー依存が大きいため、Object URLの生成・解放と状態遷移を小さく分離して確認し、コーデックごとの網羅テストは行わない。

## Open questions requiring professional review

- 6場面の名称が本人に理解しやすく、臨床用語と誤認されないか。
- 左右別の4項目で観察に十分か、項目が多すぎないか。
- 「短時間向き」「長時間でも同様」という持続性の表現が適切か。
- 感覚と本人が負担を感じる部位の選択肢に不足や誤解がないか。
- A/B差分表が改善・悪化の評価に見えないか。
